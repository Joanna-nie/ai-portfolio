# W8 开源对照反思（约300字）

**① 我的 rag_qa.py 与官方 2-Step RAG 差在哪一步？**
我的实现与官方 2-Step RAG 核心逻辑完全一致（先 Retrieve 再 Generate）。差异主要在“部署与评估”环节：官方示例偏向用 Streamlit 做网页 UI 和系统化评测，而我目前用的是 CLI 命令行交互，评估用的是 W7 设计的“幻觉对照表”（纯人工核对为主）。

**② 如果要从 2-Step 走到 Agentic RAG，我需要先补上什么能力？**
要走向 Agentic RAG（让模型自己决定何时检索），我需要先补上 **W9 的工具调用（Function Calling）** 能力。也就是让大模型能自主判断：这个问题是应该直接回答，还是需要调用查生词表、算分等工具，或者去触发知识库检索。

**③ llm-universe 没有 LICENSE，为什么只能参考思路不能复制代码？这与 .env 不入仓有何共同点？**
没有 LICENSE 意味着默认“保留所有权利”，复制代码属于侵权。而 .env 不入仓是为了保护隐私和密钥安全。两者的**共同点都是“边界与规矩”**：前者是法律和开源协议的边界，后者是系统安全的边界，作为工程师必须严格遵守，不能因为“方便”就去触碰红线。
